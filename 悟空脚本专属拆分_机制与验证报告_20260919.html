「拆分步骤1」这几个字在三份文件里都搜不到。它是宝哥对人工操作动作的口头命名 —— 所以这套机制是从产物反推规则，不是抄某处说明。这也决定了验证方式： 把反推出来的规则跑一遍，与产物逐行对账。

二、归纳出的拆分机制

复制规则

  1. 一集 = 一个表格。逐表独立处理，表格顺序＝集顺序。
  2. 字段映射：只取「台词」列。镜头 / 画面 / 备注三列与「人物｜场景｜道具」摘要行一律不进结果。
  3. 行序：严格按表格行序自上而下；单元格内部若含多个软换行（<w:br/>）或多个段落（<w:p>），按出现顺序拆成多行。
  4. 内容原样：不做语义清洗 —— 占位行（（无台词） / （无对白） / —）与空行忠实保留。 这是「复制」不是「提纯」。只做两件事：清掉行尾空白；折叠连续空行为 1 行； 整集末尾空行去掉、首部空行保留（它标记「这一行画面没有台词」，是有意义的位置信息）。

两条归一化决策。样张是人工粘贴产物、带手工痕迹，所以不逐字复刻：
① 列名「台词」不进正文 —— 样张把它写进了正文（81 集独立成行、82–84 集缀在集名后）， 但提词器会把「台词」两个字念出来；
② 空行按「折叠连续 + 去尾留首」规范化，不拟合样张的随手空行。

四、与「智能多模态拆分」的关系：同一内核，只在清洗上分叉

抽出 locateTableStructure(rows, headingBefore) 作为共用内核：表头行定位、台词列 / 角色列映射、 集标题解析、数据行区间（含「表头前的台词行被救回」）。两种拆分都调它 —— 结构识别永远一致， 行为分叉只剩一处：

维度悟空脚本专属拆分智能多模态拆分

空行保留（折叠连续、去尾留首）丢弃

口径由宝哥拍板为「内核同源 + 各自微调」：多模态保持清洗（提词器更干净）， 悟空专属严格复刻「复制」语义。两个按钮对同一份表格稿的结构与顺序完全一致， 差异只在占位行与空行这 10 行。

六、随机模糊测试抓出一个真缺陷

新增 fuzz_wukong.js：随机表格稿（列数 3~5 随机、台词列位置随机、列名六选一、分隔方式混用、 内容带全局唯一编号 T/S/N 前缀，便于字符级抓「串列」与「丢字」），8 条不变量 —— IW1 集数守恒 · IW2 非空行零丢失且顺序一致 · IW3 字段纯净（画面/备注不串列）· IW4 摘要行不入结果 · IW5 占位行保留 · IW6 空行策略 · IW7 集名正确 · IW8 双模式同源。

缺陷：占位行「连坐」吃掉同格台词 零遗漏红线

一格内容 = 甲：第一句。\n（无对白）\n乙：第二句。

修复前（整格过滤）  → 整格被丢弃，同格 3 句台词一起消失
修复后（逐行过滤）  → 只丢「（无对白）」一行，甲乙两句都保留 ✅

根因：占位行过滤拿整格文本去 test() —— if (/（无台词）/.test(t2)) return，一格里只要出现一行占位行，同格其他台词连坐消失。

修法：改成逐行过滤，新增 isPlaceholderLine(s) （认「（无台词）」「（无对白）」「无台词」「—」「-」「·」，不认「（无台词，手机屏幕微微照亮她的脸）」 这类带说明的）；有表头路径与 legacy 路径一起改。

真实稿件 228 行未变 —— 这份稿没踩到该边界（它的占位行都独占一格）。 也就是说：这个缺陷不会在宝哥当前的稿件上暴露，但边界写法必须对，而随机测试把它抓了出来。

八、两个坑（勿重犯）

  1. zsh 不对未加引号的参数做分词。set -- ${cfg} 会把整串 "1000 6 2026" 当成一个位置参数 → $1 是整串、$2/$3 空 → 脚本静默跑 0 次 （表现为「断言次数：0 耗时 0ms」，极具迷惑性）。要么 set -- ${=cfg}，要么用函数收参。 叠加老坑「变量后紧跟中文会被当作变量名的一部分」：printf "[$1篇×$2行]" 同样是错的，必须写 ${1}。
  2. 诊断脚本的判定自己也会长出缺陷。本轮 fuzz 首跑报的 4 类失败里 3 类是判定错 （isPlaceholderLine 把空行也当占位行；IW2 拿「含占位行的结果」去比「不含占位行的源」）。 先怀疑判定、再怀疑产品 —— 但不能就此收手，剩下那 1 类正是真缺陷。
