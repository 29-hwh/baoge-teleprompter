三、发现的问题

P1 高 smartSplitScripts 丢弃「首个边界之前」的内容

影响入口：preview.js:61「智能拆分（纯文字档）」按钮、index.js:183 长文本导入判定、importSave.js。3 个样本复现，100% 稳定。

只要稿件在第一个「第N集」之前有内容（剧名、出场人物表、前言），这段内容在「智能拆分」后不在任何输出块里，静默丢失：

样本首个边界前的内容（被丢弃）smart 切出
01 短剧剧名：《掌心暗渡》3 篇
04 话剧话剧《爱情疯人院》（节选） + 出场人物：周游、男子甲…1 篇
09 边界边界写法总集（说话人前缀 / 分隔 / 占位 / 标题）2 篇

根因：smartSplitScripts → findSeriesBoundaries / findHeadingBoundaries → sliceByBoundaries(lines, idxs)，切片的起点是 idxs[0]，idxs[0] 之前的行从不进入任何块。
建议：在 sliceByBoundaries 里，若 idxs[0] > 0 且其前存在非空行，先在 idxs 头部补一个下标 0，让「前言」成为独立一篇（标题走 autoName）。

P2 高 无表头旧稿：台词列不在末列时整篇台词丢失

影响入口：所有无表头（或表头未被识别）的表格稿导入。探针样本 T5b 复现。

四列「镜号 / 画面 / 台词 / 备注」且没有表头行的旧稿，多模态与悟空两条路径输出都是 0 行：

T5b 源（台词列）多模态输出悟空输出
妈妈：吃饭了，别玩手机了。 / 孩子：马上，这集看完。 / …共 4 行0 行0 行

根因：splitTableLegacy 的列推断是「≥4 列 → dialogueCol = cols-1（末列）」。末列是「备注」（空），真正的台词列被整列跳过 —— 属零遗漏红线级别。
建议：无表头时不要写死末列；改为按内容选列：在候选列里统计「像台词的行数」（cellLooksLikeDialogue），取命中最多的那一列；全空或全不命中再退回列数推断。

P3 中 「第N幕 / 第N场」两条文本路径口径不一致

影响入口：话剧 / 舞台剧类稿件。样本 04 复现。

路径结果标题
smartSplitScripts（「智能拆分」按钮）1 篇序幕　周游坐在舞台中央
splitImportBlocks(headings)5 篇…｜序幕…｜第一幕｜第二幕｜第二场（夜晚）

根因：findHeadingBoundaries 用 EP_HEAD_RE，类别字是 [集期话卷部]，不含「幕/场」；而 splitImportBlocks 的 HEAD_LINE_RE 是 [集场章节回幕篇部季话]，含「幕/场」。同一条产品，两条文本路径对「什么算标题」判定不同。
建议：让 findHeadingBoundaries 直接复用 HEAD_LINE_RE（或把 EP_HEAD_RE 的类别字补全为 [集场章节回幕篇部季话]），两条路径统一口径。

P4 低 分镜表用 ｢｣ 表示台词时，角色无法归属

AI 分镜表常写成 母亲｢回来啦，先洗手。｣、沈亦｢别——｣母亲｢吃完再走。｣ —— 用 ｢｣ 而非冒号分隔，说话人识别（依赖 名字：）拿不到角色，parseScript 后角色覆盖 0/6。文本本身零丢字、也未粘连，属「格式差异」而非丢失：台词照常进提词器，只是没有角色高亮 / 角色筛选。
建议：若要支持，可在 splitDialogueCell 增加 名字｢…｣ 这一形态的识别（左边界为行首/非汉字时优先）。

P5 低 占位形态 无 / N/A / / 未被识别为占位行

isPlaceholderLine 只认 （无台词）、无台词、无对白、破折号类。分镜表最常见的占位是单独的 无（T2 里出现 2 次），会被原样输出成一行「无」进提词器。实测识别情况：

无:N　（无台词）:Y　无台词:Y　—:Y　-:Y　（无对白）:Y　N/A:N　/:N

建议：把「整行只有一个 无」以及 N/A、／、/ 纳入占位判定。注意别误伤「无」开头的正文（只认整行恰好等于这些串）。

四、已确认可用的能力（回归基线）

  • 表格稿 8/8 全绿：一表一集、集标题识别、台词列定位（含列名变体与中间列）、角色列合并、表头在末行/中部都不吞台词。
  • 多人同格拆行（T8）：句末标点相隔、软换行、联合说话人（王建华、杨凤：不误切）、无标点真粘连（靠说话人白名单救回）—— 10 行无一粘连、零丢字。
  • 占位行逐行过滤（T7）：同格「台词 + （无对白）+ 台词」不连坐；多模态滤除占位行（4 行），悟空原样保留（8 行），两模式分工符合设计。
  • 表格前/表头前台词救回（T6、B4）：表头在表格中部或末行时，前面的台词行不被丢。
  • 极端输入健壮（B3）：空文本、纯空白、空块、空串均不崩并返回空。
  • 英文剧本（08）：SCENE N 结构被正确切成 3 篇（走「系列名+数字」识别）。

五、结论与优先级建议

  1. 表格稿链路稳：这是小程序的主用法（拍摄脚本表），8 个类型样本全项通过。唯一风险是 P2（无表头 + 台词非末列整篇丢失）—— 建议优先修，它是静默全丢。
  2. 文本稿链路的共性问题是「边界之前的内容」：P1 丢前言、P3 话剧幕/场不识别，都出在「找边界 + 按边界切」这一段。修法都不大（补下标 0 / 统一标题正则）。
  3. P4 / P5 属格式覆盖：不影响零丢字，影响观感与角色功能。可按需排期。
